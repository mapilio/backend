# Support

## Bugs And Questions

Use the repository issue forms for reproducible backend bugs, feature proposals, and documentation problems. Include the affected revision, endpoint or domain, expected behavior, actual behavior, and a minimal synthetic reproduction.

This repository does not provide an emergency production support channel or guarantees for response time. Operational incidents must follow the owning organization's private incident process.

## Do Not Open A Public Issue For

- security vulnerabilities or suspected credential exposure;
- production incidents containing sensitive operational details;
- personal data, private account information, unblurred imagery, or non-public coordinates;
- database dumps, logs, access tokens, headers, cookies, or private service configuration.

Security issues must follow [SECURITY.md](SECURITY.md). If the private vulnerability option is unavailable, do not publish the details.

Questions about the web client, mobile apps, image server, AI models, anonymizer, GeoServer administration, or infrastructure should be filed in their owning project when one is available. Backend issues may describe only the sanitized interface contract needed to diagnose cross-service behavior.

Issue screening, labels, response targets, and closure behavior are defined in the [community triage policy](docs/community/issue-triage.md). Response targets begin only after maintainers and backups are assigned for public launch and are not support guarantees.
